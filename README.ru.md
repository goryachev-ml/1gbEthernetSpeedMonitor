# 1gbEthernetSpeedMonitor

*[Read in English](README.md)*

PowerShell-скрипт для мониторинга скорости линка сетевого адаптера и её автоматического восстановления, если адаптер согласовал скорость ниже ожидаемой (например, адаптер должен работать на 1 Гбит/с, но линкуется на 100 Мбит/с).

## Что делает скрипт

- Периодически проверяет скорость линка выбранного (или автоматически определённого) сетевого адаптера.
- Если скорость опускается ниже заданного порога (по умолчанию 1 Гбит/с), скрипт логирует событие и выполняет `Restart-NetAdapter`, чтобы форсировать повторное согласование скорости с коммутатором/роутером.
- Перезапуски ограничены периодом cooldown, чтобы избежать частых повторных перезапусков адаптера ("дребезга").
- Если после перезапуска скорость всё ещё ниже порога, скрипт может (опционально) принудительно установить расширенное свойство адаптера "Speed & Duplex" в максимальное не-авто значение вместо автосогласования.
- Логирует время, прошедшее с последнего выхода системы из сна (по событию Kernel-Power 107), чтобы помочь связать падения скорости с циклами сна/пробуждения.
- Записывает все события в консоль и в лог-файл.
- Автоматически определяет язык интерфейса системы и пишет сообщения в лог на русском, если язык ОС русский, иначе — на английском.
- Автоматически выбирает "правильный" физический Ethernet-адаптер: среди активных, невиртуальных адаптеров с `PhysicalMediaType`, равным `802.3` (настоящий проводной Ethernet — это надёжнее исключает Wi-Fi, Bluetooth PAN, виртуальные/туннельные адаптеры и т.п., чем простая проверка "не 802.11"), выбирается тот, у которого сейчас самая высокая согласованная скорость линка, и в лог пишется, какой адаптер выбран. Если в системе несколько Ethernet-адаптеров и автоопределение выбирает не тот, что нужно, укажите его явно через `-AdapterName`.

## Требования

- Windows с PowerShell.
- Права администратора (требуются для `Restart-NetAdapter`).

## Использование

Запускать из PowerShell с повышенными правами (от имени администратора):

```powershell
.\1gbEthernetSpeedMonitor.ps1
```

По умолчанию скрипт автоматически выбирает самый быстрый активный физический проводной Ethernet-адаптер (см. раздел [Как это работает](#как-это-работает)). Если в системе несколько Ethernet-адаптеров и нужно мониторить конкретный, укажите его имя через `-AdapterName`.

### Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `-AdapterName` | автоопределение | Имя адаптера для мониторинга. Полезно, если в системе несколько Ethernet-адаптеров. Если не указано, автоматически выбирается самый быстрый активный физический Ethernet-адаптер. |
| `-IntervalSeconds` | `15` | Как часто проверять скорость линка, в секундах. |
| `-MinSpeedBps` | `1000000000` (1 Гбит/с) | Минимально допустимая скорость линка, в битах в секунду. |
| `-CooldownSeconds` | `90` | Минимальный интервал между перезапусками адаптера, в секундах, для защиты от "дребезга". |
| `-ForceGigabit` | `$true` | Если после перезапуска скорость всё ещё ниже порога, принудительно установить свойство "Speed & Duplex" в максимальное значение вместо автосогласования. |
| `-LogPath` | `1gbEthernetSpeedMonitor.log` рядом со скриптом | Путь к файлу лога. |
| `-CmdletTimeoutSeconds` | `20` | Таймаут на каждый вызов `Get-NetAdapter`/`Restart-NetAdapter`. Если WMI-провайдер адаптера перестаёт отвечать (бывает после нескольких быстрых перезапусков подряд), вызов прерывается по истечении этого времени вместо того, чтобы заблокировать цикл мониторинга навсегда, и попытка повторяется на следующей итерации. |

### Пример

```powershell
.\1gbEthernetSpeedMonitor.ps1 -AdapterName "Ethernet" -IntervalSeconds 10 -MinSpeedBps 1000000000 -CooldownSeconds 60
```

## Как это работает

1. Проверяет, что скрипт запущен от имени администратора.
2. Определяет целевой адаптер (по явному имени или автоматически).
3. Запускает бесконечный цикл:
   - Считывает текущую скорость линка адаптера.
   - Если она ниже порога, логирует падение, проверяет время с последнего сна/пробуждения и — с учётом cooldown — перезапускает адаптер.
   - Если после перезапуска скорость всё ещё слишком низкая и включён `-ForceGigabit`, принудительно выставляет максимально доступное значение скорости/дуплекса через расширенные свойства реестра адаптера.
   - Засыпает на `IntervalSeconds` и повторяет цикл.

## Примечания

- Скрипт читает/устанавливает свойство "Speed & Duplex" адаптера по ключу реестра (`*SpeedDuplex`), а не по локализованному отображаемому имени, так как текстовые значения зависят от языка системы, а числовые коды — нет.
- Записи в логе снабжены временными метками и пишутся как в консоль, так и в файл, указанный в `-LogPath`.
- Язык лога определяется один раз при запуске на основе `Get-UICulture` и не меняется во время работы скрипта.
- Каждый вызов `Get-NetAdapter`/`Restart-NetAdapter` выполняется с таймаутом (`-CmdletTimeoutSeconds`, по умолчанию 20 сек), чтобы зависший WMI-провайдер адаптера не мог молча заблокировать весь цикл мониторинга — вместо этого скрипт запишет сообщение о таймауте и повторит попытку на следующей итерации.
